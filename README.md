# 运营助手 · 内容工厂

> 把「爆款拆解」变成**可执行、可检查**的固定创作流程 —— 本地运行，出厂自动过平台合规审查。

一个跑在你自己电脑上的内容生产流水线：**素材库 → 选题 → 逐步向导 → 封面/图文/视频 → 出厂质检 → 数据回流**。

不联网、不上传、不需要 API Key。所有素材和产出都在本地。

---

## 为什么不是又一个「AI 写作工具」

这个项目里**没有一行 LLM 调用**。它不做两件事，因为那两件事不该由工具做：

- 不替你编观点（编出来的内容会被平台降权，也留不住人）
- 不替你写字（你的经历和判断才是内容本身）

它做的是**四件机器比人强的事**：

| | |
|---|---|
| **1. 流程约束** | 六步 SOP，上一步不过不能进下一步。卡住时明确告诉你差什么 |
| **2. 合规质检** | 32 个硬红线 + 18 个敏感词，命中**直接拦截生产** |
| **3. 批量渲染** | 一次产出多平台封面（5 风格 × 6 平台）+ 双画幅视频 |
| **4. 结构借鉴** | 从真实爆款拆出的结构库，选题自带「借鉴来源」标注 |

---

## 核心：SOP 不是模板，是流程驱动器

大多数「内容模板」是文档，写完就忘。这里的 SOP 是**代码里的状态机**：

```
① 定选题  →  ② 反差钩子  →  ③ 内容输出  →  ④ 留白互动  →  ⑤ 出成品  →  ⑥ 出厂质检
   ↓             ↓              ↓              ↓             ↓            ↓
 必须有        必须有         要点≥2条     结尾不能是     必须有       不能有
 文献依据      反差/悬念      正文≥80字    硬广           产出文件     硬红线
                             含数字或书名
```

**每一步提交时当场校验，不合格就卡住并列出具体问题。**

```
$ python3 sop.py submit <id> --step hook --text "介绍一下知识图谱"
⛔ 「② 反差钩子」未通过 —— 卡在这一步，差这些：
   · 钩子缺少反差或悬念。套这个公式：「所有人都以为 X，我实测发现 Y」

$ python3 sop.py submit <id> --step body --text "我试了一下，还行。"
⛔ 「③ 内容输出」未通过 —— 卡在这一步，差这些：
   · 要点少于 2 条 —— 内容撑不起来
   · 正文只有 9 字（建议 ≥80）—— 这是内容的灵魂，不能空
   · 正文里没有具体细节（数字／书名／版本）
   · 没有文献依据（古籍原页）
```

### 结构库从哪来

不是拍脑袋想的，是**拆了三个真实爆款**，并采纳了官媒划定的边界：

| 案例 | 数据 | 提炼的机制 |
|---|---|---|
AI 老子讲《道德经》 | 12 作品涨粉 15 万，单条点赞 10 万+ | 情境代入 → 内容输出 两段式 |
古诗解读 AI 动画 | **单条点赞 125 万** | 实测对比 |
「老祖宗回答我」 | 人民日报 / 光明网 / 央广网集体分析 | 反差感 + 参与感 |

**官媒自己在分析里划了红线**，这些红线直接变成了代码里的检查项：

| 官媒原话 | 系统里的检查 |
|---|---|
「每个老祖宗都用同样语调咆哮……把历史人物扁平化」 | 同质化检测（结构重复 / 开头重复） |
「对历史的敬重是创作底线，别让戏说变成胡说」 | 文献依据检查 |
「AI 换脸可能侵犯肖像权，需标注 AI 合成」 | 提示标注 |
「借宗教、风水、运势等噱头」 | 触发词扫描（32 硬红线 + 18 敏感） |

## 快速开始

### 先看要装什么（实测过的依赖表）

| 功能 | 需要 | 缺了会怎样 |
|---|---|---|
| 图文 / 封面 | **Pillow** | 完全用不了 |
| 素材库 | Pillow + **numpy** | 缺 numpy：校准页识别失效，配图可能混进灰阶卡 |
| **视频** | Pillow + **ffmpeg** | 视频做不了，**图文和封面不受影响** |
| 富文本剪贴板 | pyobjc-framework-Cocoa（可选） | 只少「复制富文本到剪贴板」 |
| RPA / 数据回流 | pyobjc 三家（可选，macOS 专有） | 核心功能完全不受影响 |

**Python 3.9 及以上**（实测 3.9 语法全部通过；开发环境是 3.14）。

### 安装

```bash
pip install Pillow numpy
brew install ffmpeg          # 或从 ffmpeg.org 下载静态包
```

### 跑起来

```bash
python3 make_sample.py                              # 造示例素材（真实古籍太大，不能进仓库）
python3 asset_library.py import-collection --root assets   # 建索引
python3 app_server.py                               # → http://127.0.0.1:8765
```

也可以双击 `启动运营助手.command` —— **它会先做依赖预检**，
缺什么直接告诉你装什么，不会跑到一半才报错。

打开浏览器，左侧导航：总览 / 选题 / 创作 / 素材库 / 数据 / **流程**。

### 命令行也能全流程走完

```bash
python3 topic_engine.py gen -n 12              # 生成选题
python3 topic_engine.py pick --from 候选.json -i 0   # 建项目
python3 sop.py next <id>                       # 现在该做哪一步
python3 sop.py submit <id> --step hook --text "..."  # 提交并推进
python3 pipeline.py produce <id>               # 一键生产
python3 sop.py audit                           # 全库同质化体检
```

## 素材库：用你自己的素材

素材**留在原地**，不复制、不改名、不移动。索引是可重建的 JSON。

支持两种导入方式：

**A. 已经整理好的古籍目录**（推荐）

```
assets/
  <书名>/
    SOURCE.md              # 馆藏、索书号、底本等级、册目
    <册号>/
      manifest.json        # 来源、许可、逐页清单
      images/<页码>.jpg
```

```bash
python3 asset_library.py import-collection --root assets
```

**B. 一堆散图**

```bash
python3 asset_library.py import-path ~/图片/素材
```

### 一个真实的坑：扫描校准页

数字化的古籍，**每册首页（和部分末页）是灰阶/色卡校准靶**，不是内容。实测规律极其一致：

| 页 | 暗块占比 | 是什么 |
|---|---|---|
第 0001 页 | 41–62% | 校准靶 |
部分末页 | 35–37% | 校准靶 |
正文页 | 2–15% | 古籍原文 |

`asset_library.is_content_page()` 用「暗块占比」自动识别并跳过，结果缓存到磁盘。
**如果你不处理这个，配图里会混进一堆灰阶卡。**

## 产出长什么样

一次 `produce` 得到：

```
output/
  article.html / article.txt     图文（可直接粘贴到平台编辑器）
  covers/                        多平台封面
  video_horizontal.mp4           横版（B站 / 公众号 / 知乎）
  video_vertical.mp4             竖版（小红书 / 抖音）
  发布清单.md                     逐平台标题/正文/封面/视频对照
  bundle.json
```

- **封面**：5 种风格 × 6 个平台，含 `contain_with_blur` 处理竖图放进横版
- **视频**：5 套模板、12 种转场、7 种运镜、片头片尾、多画幅
- **字幕**：Pillow 渲染透明 PNG 再叠加 —— 因为 Homebrew 的 ffmpeg **不带 libass**，`drawtext`/`subtitles` 都不可用

## 已知限制（认真说）

| | |
|---|---|
| **只在 macOS 上测过** | 核心依赖的 `say`（配音）、`h264_videotoolbox`（编码）、字体路径都是 macOS 的。核心逻辑本身可移植 |
| **需要 ffmpeg** | 必须装。Homebrew 版**没有 libass**，所以字幕走的是 Pillow 渲染方案 |
| **RPA 部分很脆** | `rpa_kit/browser_rpa/metrics_collector` 依赖屏幕分辨率和窗口布局，换台电脑就可能失效。**核心不依赖它们**，可以完全不用 |
| **没有 LLM** | 是刻意设计，不是缺陷。见上文 |
| **首次运行无素材** | 能正常启动，但素材库是空的，跑 `make_sample.py` |

## 项目结构

```
核心（可独立运行）
  asset_library.py    素材库：就地索引、内容页识别、CJK 检索
  topic_engine.py     选题引擎：爆款结构 + 书目知识库 + 数据反馈
  sop.py              创作 SOP：流程驱动 + 出厂质检
  content_ops.py      内容运营：项目状态机、图文模板、富文本剪贴板
  cover_studio.py     封面：5 风格 × 6 平台
  video_studio.py     视频：模板、转场、运镜、字幕
  pipeline.py         编排：一键产出全部成品
  app_server.py       本地 Web 界面（http.server，零框架）
  ui/                 前端（原生 JS，无构建）

可选（macOS 专有，脆）
  rpa_kit.py          像素级 RPA：窗口、截图、点击、输入
  browser_rpa.py      浏览器会话：开标签、登录等待、热点保护
  metrics_collector.py 数据回流：Vision OCR 读平台后台
  rpa_example.py      用法示例

工具
  make_sample.py      生成示例素材库
```

## 设计原则

1. **发布按钮永远由人点** —— 工具只填草稿，不做全自动发布。平台对「非真人自动化创作」有明确规则，这条线不该越
2. **内容只能来自你** —— brief 里没有真实经历时，工具**拒绝生成**
3. **合规检查前置** —— 不是发出去被限流才发现，而是生产前就拦下
4. **素材原地不动** —— 索引可丢可重建，你的文件永远是你的
